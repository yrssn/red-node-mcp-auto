# 计算机技术需求预置

在项目根启动服务后，执行：

```powershell
./scripts/seed-programming.ps1
```

默认写入本机正式服务 `http://127.0.0.1:18061` 的 MySQL 工作空间。演示环境使用 `-BaseUrl http://127.0.0.1:18060`；开启访问凭证后传入 `-Token` 或设置 `AUTH_TOKEN`。脚本通过现有控制台 API 添加配置，不访问小红书、不抓取帖子、不发送评论。

预置包含：

- 7 个找帖任务：Java、Spring Boot、PHP、Vue、Python、MySQL、计算机项目开发；共 22 个关键词或话题来源。
- 3 个评论策略：具体技术建议、需求澄清、默认停用的单个文字表情示例。
- 9 条素材：各技术栈排错要点、需求澄清、表情使用参考及默认不参与生成的单个表情。

同名配置保留现有内容，重复执行只补齐缺失项。导入会暂停全局发送队列；新任务均暂停、手动运行、人工审核、关闭自动入队，且任务发送阶段暂停。每轮获取上限 5 条、发送额度 1 条只是保守的本地配置，不代表平台允许的频率或安全阈值。已有同名任务不覆盖，需自行核对其开关。

预置任务默认暂停并采用人工审核，运行前选择文本模型和启用的策略。图片文字由本地 OCR 补全，见 [OCR 说明](ocr.md)。

任务面向原帖主动提出的编程求助、调试和合法开发需求，不用昵称、外貌推测身份。排除论文代写、代考、冒名提交等作弊服务和无关营销；不把无交流意图的技术分享当作合作邀请。关键词只用于发现候选内容，是否适合交流仍需结合原帖人工判断。

## 表情支持

策略、素材和评论编辑框可以点击插入 `🙂 😊 👍 💻 🤝`，也可以粘贴文字 emoji。插入仅修改输入框，不保存或发送。单个表情可手动填写；预置单表情策略默认停用，避免重复刷屏。当前不支持图片、GIF 或小红书原生表情包，不会把图片链接伪装成表情。

素材库可以另外保存静态 PNG、JPEG 图片参考附件（512 KiB 内），并预览或替换，GIF 暂不支持。参考附件不发送给 AI，也不会自动贴到评论；图片/原生收藏表情发送仍未接入。带“接单”等文字的图片同样需要结合实际语境和平台营销规则判断，不能把图片当作规避审核的方式。

- [小红书社区公约 2.0](https://pgy.xiaohongshu.com/help/detail?id=1eda0a065dd894063c2e029a49e8f6a1&userType=4)要求真诚分享、友好互动，反对刷屏、骚扰、滥发营销、虚假人设和伪造口碑；建议主动标明 AI 辅助创作。因此两条 AI 策略包含 AI 辅助说明，不编造经历，不留站外联系方式。
- 同一公约要求经营身份透明，并使用平台提供的工具完成交易。涉及开发服务经营时，需要先核实自己的经营身份、行业资质和服务准入，不能通过评论规避交易规则。
- [官方聚光账号准入说明](https://ad.xiaohongshu.com/next_help/docs/195c5fe505c71b4b0335a2fe0d61d8e0)将论文代写、代考等列为不支持的非法教育服务。这是商业准入规则，不能解释为其他场景均被允许。
- [2026-03-10 AI 托管治理公告（澎湃刊载，来源署名薯管家）](https://www.thepaper.cn/newsDetail_forward_32741496)指出，利用技术模拟真人、非真实创作或虚假互动受到治理，AI 托管互动可能被警告、限制分发或封禁。因此不能把“人工通过后由程序代发”或“只发一个表情”视为已获平台许可。

文字表情、较低频率、关键词过滤和人工审核都不能保证账号不受处罚，浏览器自动化本身也不等于平台授权。建议先把系统作为候选帖子和回复草稿管理工具，核实原帖与当前平台要求后，由本人在原帖手动互动。遇到平台警告、限制或验证应停止相关任务，先通过官方渠道处理；不要绕过限制或更换账号继续刷屏。
