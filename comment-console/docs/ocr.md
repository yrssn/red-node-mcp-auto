# 图片文字识别与省费筛选

旧版只读取帖子标题和描述，图片里的“JavaWeb 作业、急求”等正文没有进入分析；只看话题标签会漏掉需求。现在会提取帖子自身图片，使用本地 OCR 补全图片文字，并将 OCR 与判断依据一起存入 MySQL。只读取已加载的原作者评论作为补充，不把其他人的接单留言混成发帖需求。

## 本地启动

首次安装，在项目根执行：

```powershell
./scripts/install-ocr.ps1 -PythonPath 'D:/anaconda/python.exe'
./scripts/start-ocr.ps1
./scripts/start.ps1
```

可换成自己的 Python 3.11–3.13 x64 路径。依赖放在项目的 `.runtime/ocr`，不改系统 Python。正式模式启动脚本会尝试复用或启动本地 OCR；演示模式不访问站点、OCR 或外部模型。OCR 没装好时系统仍可打开，有图片的候选标成“待人工确认”，不会仅凭标签断言没有需求。

OCR 地址默认 `http://127.0.0.1:18063`。`OCR_URL` 可指定自己的服务；`OCR_ENABLED=false` 禁用。系统设置中可手动检查连接。Docker Compose 已包含独立 OCR 容器，应用通过内部网络访问，OCR 端口不映射到宿主或公网。

若本机 TUN 代理将小红书 CDN 解析为 `198.18.0.0/15` 的虚拟地址，可从 `backend/config/ocr.example.json` 创建私有的 `ocr.json`，设置 `allow_fake_ip=true`，再重启本地服务；也可通过 `OCR_ALLOW_FAKE_IP=true` 配置。默认关闭。该兼容仅适用于已允许的小红书 HTTPS CDN 和上述虚拟地址段，仍保留证书主机校验，其他内网地址继续拒绝。本工作区已按实际 TUN 环境启用，私有配置不打包。

采用 [RapidOCR 官方本地 CPU 方案](https://rapidai.github.io/RapidOCRDocs/main/en/install_usage/rapidocr/install/)，没有 OCR 账号、API Key 或第三方按次计费，仍会使用本机 CPU/内存。首次安装需下载 Python 依赖；固定 wheel 内含模型，运行时从本地加载。

## 三种分析模式

帖子里的图片由本地 OCR 逐张提取文字。标题、正文、已加载的作者补充和 OCR 文字一并交给文本模型；相关词和排除词作为模型判断条件。原图不传给模型。原规则任务会切换为文本模型并关闭自动入队，未绑定模型的任务会暂停，配置模型后可重新运行。

图片失败、服务不可用或只识别部分图片，标“待人工确认”，不判为无需求。每帖 OCR 总超时 45 秒；图片最大 10 MiB/1600 万像素。重复图片内容有最多 256 条内存缓存，减少重复推理；重启后缓存重建。下载仅允许已验证的小红书 HTTPS CDN，不携带 Cookie 或模型密钥。图片只发给配置的 OCR 服务，不发给语言模型；语言模型只接收 OCR 文字。

## 重新分析已有候选

候选列表或详情点“重新分析”，只刷新这一条的详情、OCR 和筛选结果，不抓取新帖子、不生成或发送评论。有任务运行、或该帖已有有效评论草稿/发送记录时先处理对应状态。

作者原文或已加载补充中明确表示“找到了”“已解决”，显示“需求已结束”；这与“没有需求”分开。作者评论未加载到时不能保证判断到，OCR 结果和原作者补充均可在详情中核对。

任务中可开启“保留已结束需求”：结束标记继续保留，帖子仍需通过技术词、需求词、排除词和图片信息检查；相关内容进入“待人工确认”，不自动生成或发送回复。未开启时继续按需求已结束归档。修改开关后可对已有候选重新分析。

候选详情支持本人填写相关文字和 emoji，保存为人工草稿。无需模型，按当前启用策略的长度和禁用词校验，并按账号与帖子跨任务去重；只创建待审核记录，不自动入队或恢复发送。已有记录应继续编辑原记录。已结束帖的草稿只能手工编辑，不自动重新生成。

模型匹配只是发现相关候选，不代表平台允许相关服务或自动评论。任务排除词、人工审核、全局发送开关继续生效；不会因 OCR 匹配而自动恢复发送。
