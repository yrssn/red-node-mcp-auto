# 功能使用

## 启动和账号

本地使用项目根的 scripts/start.ps1，默认启动正式模式并监听 18061；-Demo 使用 18060。Docker 使用 deploy 中的配置，默认宿主端口 18062。

本地想观察页面操作，用 `scripts/start.ps1 -ShowBrowser` 启动（源码启动加 `-headless=false`）。显示模式在服务启动时确定，已有服务需要先停止；开始账号检查、找帖等操作时浏览器才会打开。这个开关不会自动运行任务或恢复评论发送队列。

手动登录检查、搜索和详情等步骤分别创建浏览器，步骤结束后会自动关闭窗口；OCR 与 AI 分析阶段通常没有浏览器窗口。页面空闲时只读取账号展示缓存，不会为定时刷新或切回页面而打开浏览器。

搜索直接等待笔记结果数据就绪，不要求动态页面完全静止。读取搜索来源、帖子详情、OCR 或模型超时会分别显示对应阶段；搜索失败不再统一提示重新登录。无法确认筛选结果刷新时会明确报错，避免把旧排序结果当作新结果。

正式账号登录：右上角「账号登录」→「获取登录二维码」→小红书 App 扫码确认→「检查登录状态」。系统会保存 Cookie 和指纹 seed，登录失效后重新扫码。

页面刷新、定时刷新和切回页面均只读取账号展示缓存，尚未核实时显示“账号待检查”；不会自动访问小红书，也不会因网络错误直接当作退出。手动“检查登录状态（强验证）”、运行任务、保存人工草稿和发送前仍会实时核实账号，成功后更新展示缓存。发送身份判断不使用缓存代替；接口异常显示中文错误，不要求直接重扫二维码。

演示模式使用独立 MySQL 库，找帖、分析和发送均为模拟。当前仍是单账号版本，本次目录整理不增加多账号功能。

## 配置模型和评论策略

模型配置填写名称、Chat Completions 兼容 API 基础地址、模型标识和密钥，并测试连接。基础地址通常以 /v1 结尾。密钥保存后不随状态 API 返回。

评论策略支持 AI 生成或固定话术，设置语气要求、最大字数和禁用词。修改策略会递增版本，已经生成的评论保留原策略快照。素材库中的启用素材作为 AI 的参考知识。

素材可以附一张静态 PNG 或 JPEG 参考图片，支持预览、替换与移除，大小不超过 512 KiB；GIF 暂不支持。图片随素材存入 MySQL，仅供人工参考，不发送给外部 AI 模型，也不进入评论发送流程。手机界面截图应标明“参考截图，待补表情原图”，避免误当成待发送图片；后续可在编辑素材中替换原图。素材附件能力不代表已支持小红书图片或原生收藏表情评论。

## 发现帖子

创建任务时可以组合多个来源：

- 关键词：按最新结果搜索，支持发布时间和图文/视频筛选。
- 话题词：以话题词搜索，并非独立话题页全量采集。
- 用户主页：读取指定主页当前可访问的笔记。
- 帖子链接：直接读取完整 HTTPS 链接，保留 xsec_token；短链接需先展开。

配置 AI 分析目标、排除词、模型、策略、每轮获取和发送上限。任务创建后默认暂停，点击运行一次或启用定时刷新。找帖、分析和发送可分别暂停。

最多同时处理两个任务，更多任务按请求顺序排队；同账号的浏览器操作依次执行，OCR 与分析可在另一个任务访问页面时继续处理。评论发送使用独立的串行队列，仍受全局暂停、任务发送开关、账号核验和发送间隔控制。

任务页显示排队、当前阶段和处理进度；重复点击已排队或运行中的任务不会再追加一轮。每个任务的“累计帖子”“已分析”根据已经保存的数据实时更新，“查看帖子”“查看日志”直接定位该任务的结果。搜索无结果时可以清空筛选，不会误显示为尚未创建任务。

可以先保存暂停任务，运行前须选择有效的文本模型和已启用的策略。Java、Spring Boot、PHP 等示例配置可使用 `scripts/seed-programming.ps1` 导入，见 [技术需求预置](programming-presets.md) 和 [OCR 与省费筛选](ocr.md)。

## 评论管理

评论按草稿、待审核、待发送、发送中、已发送、失败、待确认、跳过和取消管理。

查看详情可以同时看到原帖、AI 判断理由、评论文本、AI 原稿、策略版本和操作历史。支持修改、重新生成、审核、跳过、取消排队和 CSV 导出。

候选详情也可以直接写人工草稿，保存后进入待审核，不调用模型或自动发送。若想保留作者已找到帮助的帖子，在任务中打开“保留已结束需求”并重新分析；结束状态仍单独展示，相关候选仅供人工核对语境后交流。

策略、素材、评论编辑支持文字 emoji 快捷插入，不会自动发送；暂不支持图片或小红书原生表情包。

同一账号、同一帖子跨任务去重。发送异常和重启时中断的评论进入待确认，先到原帖核实，再选择已发送或未发送；不会直接自动重试。已发送记录不可修改或重发。

## 发送控制

服务每次启动后全局发送队列均暂停。发送必须同时满足：评论已入队、任务未暂停、任务发送阶段未暂停、全局队列已恢复、账号一致且本轮额度未用尽。

全局发送间隔可在设置中调整；每轮发送额度保存到 MySQL。暂停不撤回已经提交给站点的请求。

开启全局队列后，任务本身或任务发送阶段仍可能暂停。待发送记录会展示实际阻塞原因，包括两个暂停开关、本轮额度、策略或数据库问题，以及等待间隔/账号核验；“已启用”不等于已经向站点提交。可从评论跳转到对应任务查看发送开关，界面不会自动解除暂停。确定未提交前不要反复取消、重建或重发。

## 数据和凭证

- 正式连接：backend/config/mysql.json 的 dsn，或 MYSQL_DSN。
- 演示连接：同文件的 demo_dsn，或 MYSQL_DEMO_DSN。
- 外部 Docker MySQL：backend/config/mysql.docker.json。
- 本地会话：backend/data/cookies.json。
- Docker 会话：session_data 持久化卷。

密码、Cookie、模型密钥属于私有数据，不在交付 ZIP 中。MySQL 存储格式和表结构保持不变；单工作空间采用 JSON 快照和 revision CAS，推荐每库一个服务实例。
